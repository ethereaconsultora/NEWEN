## CONTEXTO

Integrar la app **Anima** (gestión clínica) como anexo importante dentro de Newen,
en la misma línea que el Campus (hoy solo maqueta). Dentro de Newen se llama
**"Mi consultorio"** y vive en el panel del counselor.

Restricción crítica indicada por el usuario: trabajar **únicamente** con las cuentas
de Supabase, GitHub y Vercel de **Newen** (las de Anima quedaron cerradas).

Fuente de referencia: carpeta raíz `anima-new` (Desktop), módulos reales:
`Inicio`, `Pacientes`, `Agenda`, `Calendario`, `Pagos`, `Resumen`, `Ajustes`.

Antes de codificar se entregó maqueta visual interactiva `consultorio-maqueta.html`
(raíz del workspace) para validar el funcionamiento visual. Validada por el usuario:
- Pestaña "Consultorio" primera en la barra inferior.
- Sin temas de Anima por ahora: hereda la identidad visual de Newen.

## PROBLEMAS

1. **Rutas de import de CSS modules** — los `page.tsx` en subcarpetas
   (`nuevo/`, `[id]/editar/`) referenciaban `pages.module.css` con `../` incorrecto.
   El build de Next detectó 3 errores (`module-not-found`). Corregido a `../../` y
   `../../../` según profundidad. `tsc --noEmit` no lo detectó porque Next genera los
   tipos de CSS modules; solo el build lo expone.

2. **Conflicto de versión** — la migración se creó como `v0.22.0`, pero v0.22.0 ya
   estaba tomado por "Panel Admin + postulaciones". Renombrado a `v0.23.0`.

---

## DECISIONES

- **DD: Autenticación** — el consultorio usa el auth de Newen (`@/lib/supabase/*`).
  `user_id` de las tablas clínicas = `auth.uid()` del counselor (consistente con
  `users` y `counselors`).
- **DD: Identidad visual** — el módulo hereda los design tokens de Newen (verde
  `#1B4332`, paleta cálida, DM Serif Display + DM Sans). Los temas de Anima quedan
  para una versión futura (decisión del usuario).
- **DD: Arquitectura de páginas** — lecturas como Server Components, formularios
  interactivos como Client Components (mismo patrón que Anima).
- **DD: Nombre** — "Mi consultorio" como pestaña y marca interna del módulo.
